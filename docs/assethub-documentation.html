Dokumentasi AssetHub

Panduan lengkap untuk menyiapkan, menjalankan, menggunakan, dan merawat aplikasi IT Asset Management berbasis Laravel, Blade, Bootstrap, MariaDB, dan XAMPP.

Target pembaca: pengguna awam Windows yang ingin menjalankan project di PC lokal.

1. Gambaran Umum

AssetHub adalah aplikasi untuk mencatat dan mengelola aset IT perusahaan. Aplikasi ini berjalan secara lokal menggunakan web server bawaan Laravel dan Vite untuk asset frontend.

Backend
Laravel 12, PHP 8.2 atau lebih baru, Blade.
Frontend
Bootstrap 5 dan Bootstrap Icons melalui Vite.
Database
MariaDB/MySQL dari XAMPP.
QR Code
QR Code unik untuk setiap aset, dapat dicetak dan dipindai.

2. Persiapan PC

Install software berikut sebelum melakukan clone:

SoftwareKegunaanPemeriksaan
XAMPPPHP dan MariaDB/MySQL lokal.php --version
ComposerMenginstall dependency PHP/Laravel.composer --version
Node.js LTSMenjalankan Vite dan dependency frontend.node --version
npmPackage manager frontend.npm --version
GitClone dan mengambil update repository.git --version

Versi dan konfigurasi yang disarankan

  • Windows 10 atau 11.
  • PHP 8.2 atau lebih baru. Pastikan extension openssl, mbstring, pdo_mysql, fileinfo, dan ctype aktif.
  • Gunakan Node.js versi LTS.
  • Pastikan folder PHP XAMPP masuk ke PATH Windows, atau jalankan command dari shell XAMPP.
Catatan: XAMPP Control Panel perlu dijalankan sebagai Administrator jika Windows menolak start Apache atau MySQL.

3. Clone Project ke PC Lokal

  1. Install Git.
  2. Buka PowerShell atau Git Bash.
  3. Pindah ke folder tempat project akan disimpan, misalnya Documents.
cd "$HOME\Documents"
git clone https://github.com/SetiyawanID/assetmanagement.git
cd assetmanagement

Pastikan file seperti artisan, composer.json, package.json, dan folder database terlihat di folder project.

4. Menyiapkan MariaDB dari XAMPP

4.1 Start MySQL

  1. Buka XAMPP Control Panel.
  2. Klik Start pada MySQL.
  3. Apache tidak wajib dinyalakan karena aplikasi menggunakan php artisan serve. Apache boleh digunakan jika diperlukan untuk project lain.

4.2 Membuat database

Buka http://localhost/phpmyadmin, klik New, lalu buat database bernama assethub. Gunakan collation utf8mb4_unicode_ci jika tersedia.

Alternatif melalui SQL:

CREATE DATABASE assethub
CHARACTER SET utf8mb4
COLLATE utf8mb4_unicode_ci;

4.3 Konfigurasi file .env

Salin file konfigurasi contoh:

Copy-Item .env.example .env

Buka file .env dengan VS Code, lalu pastikan bagian database seperti berikut:

APP_NAME=AssetHub
APP_ENV=local
APP_DEBUG=true
APP_URL=http://localhost

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=assethub
DB_USERNAME=root
DB_PASSWORD=

Pada instalasi XAMPP standar, user database adalah root dan password kosong. Jika password root Anda berbeda, isi DB_PASSWORD.

5. Install Dependency dan Menyiapkan Aplikasi

Jalankan command berikut dari folder project:

composer install
php artisan key:generate
npm install
php artisan migrate --seed
Peringatan: php artisan migrate:fresh --seed akan menghapus semua tabel dan data. Gunakan hanya pada database baru atau saat sengaja ingin mengulang data demo.

Untuk project yang sudah memiliki database lama, gunakan php artisan migrate saja. Jangan menjalankan migrate:fresh karena akan menghapus data aset.

6. Menjalankan AssetHub

Gunakan dua terminal PowerShell yang berbeda.

Terminal 1: Laravel

cd "$HOME\Documents\assetmanagement"
php artisan serve

Buka aplikasi di http://127.0.0.1:8000.

Terminal 2: Vite

cd "$HOME\Documents\assetmanagement"
npm run dev

Vite biasanya berjalan di http://localhost:5173. Tab terminal harus tetap terbuka selama development.

Command yang benar: gunakan php artisan serve, bukan php artisan server. Gunakan npm run dev, bukan npm start.

Mode tanpa Vite

Untuk menjalankan hasil build frontend:

npm run build
php artisan serve

Mode ini berguna untuk simulasi tampilan production. Jalankan ulang npm run build setelah mengubah CSS atau JavaScript.

7. Akun dan Hak Akses

RoleAkses utama
Super AdminAkses semua workspace, membuat Admin/User langsung, CRUD semua master data, approve/reject semua pengajuan, force reset password Admin lain, dan melihat historical approval.
AdminMengelola aset, membuat User melalui approval, mengajukan perubahan akun/divisi/kategori/status, melihat status pengajuan sendiri, dan mengganti password sendiri.
UserTidak memiliki akses workspace IT. User hanya menjadi pemegang/assignee aset dan tidak dapat login ke workspace.

Tidak ada pendaftaran publik. Akun baru dibuat dari menu Kelola akun oleh Admin atau Super Admin.

8. Fitur AssetHub

8.1 Dashboard/Ringkasan

Menampilkan total aset, aset tersedia, aset assigned, aset maintenance, aset terbaru, komposisi kategori, dan jumlah lokasi.

8.2 Semua Aset

  • CRUD aset: asset tag, nama, kategori, serial number, brand, model, lokasi, pemegang, status, kondisi, pembelian, garansi, dan catatan.
  • Search nama, asset tag, dan serial number.
  • Filter berdasarkan kategori dan status.
  • Pagination agar daftar besar tetap ringan.
  • QR Code unik otomatis untuk setiap aset.

8.3 QR Code Aset

Ikon QR Code pada kolom Aksi membuka popup print. QR Code dicetak dengan ukuran 2 x 2 cm, nama aset dan serial number berada di sampingnya, serta outline tipis untuk batas potong stiker. Saat dipindai, QR Code membuka halaman detail aset setelah autentikasi.

8.4 Kelola Akun

  • Search nama/email, filter role, filter divisi, CRUD akun, dan pagination.
  • Admin hanya dapat mengelola akun User.
  • Edit dan hapus oleh Admin masuk approval.
  • Super Admin dapat mengelola semua akun sesuai rule role.
  • Ganti password tersedia pada menu user di pojok kanan atas.
  • Super Admin dapat force reset password akun Admin lain.

8.5 List Divisi

CRUD divisi, search nama/deskripsi, filter divisi yang sudah atau belum memiliki akun, dan approval untuk tambah/edit/hapus oleh Admin.

8.6 Kelola Kategori

CRUD kategori, icon Bootstrap Icons, search, filter kategori yang digunakan atau belum digunakan aset, serta approval untuk operasi Admin.

8.7 Kelola Status

CRUD status aset dengan slug dan warna badge. Status tampil dinamis pada form dan filter aset. Operasi Admin memerlukan approval.

8.8 Notifikasi dan Approval

Ikon bell muncul di topbar. Super Admin melihat jumlah pengajuan pending. Admin melihat badge saat pengajuannya sudah disetujui atau ditolak. Riwayat tetap disimpan sebagai Pending approval, Approved, atau Rejected.

8.9 Tema dan Responsive

AssetHub menggunakan tema gradasi purple, Bootstrap responsive layout, tooltip ikon, dan tampilan yang menyesuaikan desktop maupun mobile.

9. Alur Approval

  1. Admin membuka form atau aksi CRUD.
  2. Admin mengirim perubahan.
  3. Data approval disimpan sebagai Pending approval dan data aktif belum berubah.
  4. Super Admin menerima badge pada ikon bell.
  5. Super Admin membuka halaman Items yang perlu di approve.
  6. Super Admin memilih Approve atau Reject.
  7. Jika Approved, perubahan diterapkan. Jika Rejected, data aktif tetap seperti sebelumnya.

Sistem mencegah beberapa Admin mengajukan perubahan pending pada item yang sama. Warning menampilkan nama Admin yang sudah mengajukan perubahan tersebut.

10. Backup dan Perawatan

Backup database melalui phpMyAdmin

  1. Buka http://localhost/phpmyadmin.
  2. Pilih database assethub.
  3. Klik Export.
  4. Pilih format SQL dan klik Export.

Update project

git pull origin main
composer install
npm install
php artisan migrate
npm run build

Jangan menghapus file .env saat update. File tersebut berisi konfigurasi lokal dan tidak seharusnya di-commit ke Git.

Cache setelah perubahan

php artisan optimize:clear
php artisan view:cache

11. Troubleshooting

MasalahSolusi
php tidak dikenaliTambahkan folder PHP XAMPP, biasanya C:\xampp\php, ke Environment Variables PATH. Tutup dan buka ulang terminal.
Composer gagal installPastikan PHP aktif, internet tersedia, dan extension PHP yang disebut pada bagian persiapan aktif.
SQLSTATE access deniedPeriksa MySQL XAMPP sedang running dan cocokkan DB_USERNAME/DB_PASSWORD di .env.
Unknown database assethubBuat database assethub melalui phpMyAdmin atau SQL.
Table not foundJalankan php artisan migrate. Untuk database demo kosong gunakan php artisan migrate --seed.
Port 8000 sudah dipakaiJalankan php artisan serve --port=8001, lalu buka http://127.0.0.1:8001.
Port Vite sudah dipakaiVite biasanya memilih port berikutnya secara otomatis, atau hentikan proses Vite lama dengan Ctrl+C.
CSS/JS tidak berubahPastikan npm run dev aktif. Jika memakai mode build, jalankan npm run build lalu hard refresh browser dengan Ctrl+F5.
Error setelah mengubah .envJalankan php artisan optimize:clear, lalu restart php artisan serve.
Data hilang setelah migrate:freshPerintah tersebut memang menghapus data. Restore database dari backup SQL dan hindari command itu pada database production.
